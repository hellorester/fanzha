# 原型实施基线

依据：项目《原型系统详细实施计划》版本 1.0。目标为单机离线 Vue 3 + Spring Boot + MySQL 原型。

## 范围与规则

本轮实现公共登录 M0、群众 M1、反诈中心 M2、支付机构 M3、网格 M4。包含返还、申诉、宣防、统计、配置、附件、审计与备份恢复。外部监测、实名资料、银行账户与资金操作均为明确标注的模拟数据；权限、金额、状态与持久化真实执行。

|规则|实施口径|
|---|---|
|R01|名称为反诈协同处置平台；四类业务角色，中心管理员为中心内部权限|
|R02|五因子规则评分；24小时固定归并窗；无真实银行和运营商接口|
|R03|所有风险等级经中心核实后派发；止付还需明确目标资金账户及证据关联。未查明账户时可只派上门核查，不能任意选择账户|
|R04|同一预警按目标账户区分派发：首次创建，有效指令重复派发复用原单号；失败后只能从原指令复核重发并保留关联，解除后不能普通重建；其他账户可独立派发，上门任务保持唯一、缺失时原子补齐|
|R05|指令/任务状态与执行结果分列；提醒为事件|
|R06|申诉成立生成解除指令；有效执行后才解除原止付|
|R07|匿名凭受理编号及随机凭证查询脱敏摘要；凭证摘要入库；空主体不归并|
|R08|关联线索逐条按同一配置评分，取最高总分；已派单保持状态并标记补充复核，通过前不能派发或重发新的止付，已有执行任务继续办理|
|R09|缺失因子0分；夜间[23:00,05:00)；首条受理时间起24小时含边界|
|R10|成功冻结起48小时；延期每次48小时，最多2次；受理/回执30分钟超时；派发、受理、回执、申请、补正、审核、延期及更正在资金行锁就绪后检查期限，到期先释放资金并保存账本再拒绝办理，超时转督办；提醒按有效期版本去重|
|R11|联动止付须两端有效反馈；仅上门核查须网格有效反馈并记录核查结论。中心处理异常、确认办结才闭环；冻结及后续申请独立跟踪|
|R12|宣防与劝阻分离；触达按人次；更正经审批追加版本，有后续资金依赖时拒绝直接更正|
|R13|派发前更正核验受害人同步关联举报并记录原/新身份，提交账号不变；派发后不改归属|
|R14|新止付派发与失败重发共用有效状态、无待复核线索、最近人工复核通过且对应当前复核人的条件；重发理由不代替人工复核；返还、申诉、解除及其允许的失败重发按独立规则办理|
|R15|规则异常保留举报并记录举报ID、原始异常及调用栈，中心可从详情重新研判原记录；不以重复创建举报代替恢复|
|R16|拒绝执行更正为成功冻结时，申请和批准两次检查有效人工复核及预警状态；重新冻结开启新的时效周期。更正申请先校验结果、金额、原回执和资金依赖，批准时再次检查|
|R17|原冻结解除或更正为拒绝时，尚未核定、受理、审核或补正的申请转已失效并记日志；已作出的核定、裁定保留，执行状态单独跟踪。原冻结解除时未审核更正也失效；群众补正须仍为原申请人且保持冻结账户户主的有效核验关联|
|R18|超期未回传和劝阻未完成的上门任务进入中心督办，可跳转原任务办理；超期不阻止补做回传。网格员有待上门或劝阻中任务时，不得直接停用、跨社区调动或移出网格角色，须先交接或完成回传|
|R19|中心可结束或取消宣防任务；完成须有至少一次活动记录，结束后停止新增打卡，既有活动、人数及结束说明保留|

## 身份与账户关系补充口径

这一节修正早期方案混用举报人、受害人和冻结账户户主的问题，不视为原需求已经明确规定。

|对象/关系|执行规则|
|---|---|
|群众登录账号→实名人员|同一实名人员只允许一个启用的核验账号。历史 `af_victim` 表复用为实名人员资料；其名字不意味着每个人都是受害人|
|实名人员→资金账户|零到多个，由中心核对开户依据登记；`af_bank.owner_person_id` 是户主，不能用举报人或预警受害人代替|
|举报人→受害人|只有明确选择本人受损且实名有效时初始关联本人；代他人举报或提供线索由中心另行核验|
|举报线索→资金账户|号码/网址不能直接换算银行账户。账号精确匹配或历史核验仅为候选；`af_alert_bank`逐案记录依据、关联举报、核验人及时间；变更关系后须重新复核|
|受害人→返还|仅中心确认的受害人可申请，并绑定本人收款账户。申请和审核记录保存实名主体与收款账户，执行时再次核验|
|冻结账户户主→申诉|仅账户实名户主可申请，不以举报人或受害人身份自动授权。不同案件下一个人可以同时具有不同关系|
|返还入账|返还执行在同一事务中减少原冻结、增加本人收款余额并保存转出和入账流水；跨账户按编号排序加锁。对账按期初＋入账－转出＝可用＋冻结独立检查|
|缺少资金账户|核验当事人/社区后可先上门核查，回传后中心闭环；后续查明资金账户可关联、复核再派发止付，复用原上门任务|
|历史记录|升级不猜户主、不自动认可旧的任意派发关系；缺少关系的未执行旧止付转中心核验重发，缺少申请依据的未完成旧申请停止并释放占用，保留历史意见和已执行资金|

## 页面及操作

公共：登录、匿名举报、凭证查询、知识文章。群众：总览、举报、办理记录、本人资金账户、返还、户主申诉。中心：总览、研判/复核、线索账户核验、联动派发/单独上门、时效、返还核定、申诉裁定、实名人员、账户归属登记、宣防、知识、账号、黑名单、配置、日志、更正。支付：指令、资金账户、回执、更正、统计。网格：任务、到场与过程、宣防打卡、社区统计。详情保留申请人及收款账户、关联单号、状态、时间线与明确失败提示。

## 验收与推进

沿计划步骤01—40推进；实现记录和实际测试证据分别保存。正常、匿名、归并、部分/拒绝执行、劝阻未完成、到期、返还、申诉及越权为必须覆盖场景。每个业务动作由后端身份、范围、当前状态和输入共同校验。SQL使用绑定参数；跨表操作置于事务；并发占用/回执/到期使用行锁和唯一约束。
