# 原型实施基线

依据：项目《原型系统详细实施计划》版本 1.0。目标为单机离线 Vue 3 + Spring Boot + MySQL 原型。

## 范围与规则

本轮实现公共登录 M0、群众 M1、反诈中心 M2、支付机构 M3、网格 M4。包含返还、申诉、宣防、统计、配置、附件、审计与备份恢复。外部监测、实名资料、银行账户与资金操作均为明确标注的模拟数据；权限、金额、状态与持久化真实执行。

|规则|实施口径|
|---|---|
|R01|名称为反诈协同处置平台；四类业务角色，中心管理员为中心内部权限|
|R02|五因子规则评分；24小时固定归并窗；无真实银行和运营商接口|
|R03|所有风险等级经中心核实后联动派发；缺主体、社区、机构或账户先补录|
|R04|重复派发返回既有单号；缺失的一端原子补齐|
|R05|指令/任务状态与执行结果分列；提醒为事件|
|R06|申诉成立生成解除指令；有效执行后才解除原止付|
|R07|匿名凭受理编号及随机凭证查询脱敏摘要；凭证摘要入库；空主体不归并|
|R08|关联线索逐条按同一配置评分，取最高总分；已派单保持状态并标记补充复核|
|R09|缺失因子0分；夜间[23:00,05:00)；首条受理时间起24小时含边界|
|R10|成功冻结起48小时；延期每次48小时，最多2次；受理/回执30分钟超时；提醒按有效期版本去重|
|R11|两端有效反馈并经中心处理异常、确认办结才闭环；冻结及后续申请独立跟踪|
|R12|宣防与劝阻分离；触达按人次；更正经审批追加版本，有后续资金依赖时拒绝直接更正|

## 页面及操作

公共：登录、匿名举报、凭证查询、知识文章。群众：总览、举报、办理记录、返还、申诉、资料。中心：总览、研判/复核、协同处置、时效、返还核定、申诉裁定、宣防、知识、账号、黑名单、配置、日志、更正。支付：指令、模拟账户、回执、更正、统计。网格：任务、到场与过程、宣防打卡、社区统计。详情保留关联单号、状态、时间线与明确失败提示。

## 验收与推进

沿计划步骤01—40推进；实现记录和实际测试证据分别保存。正常、匿名、归并、部分/拒绝执行、劝阻未完成、到期、返还、申诉及越权为必须覆盖场景。每个业务动作由后端身份、范围、当前状态和输入共同校验。SQL使用绑定参数；跨表操作置于事务；并发占用/回执/到期使用行锁和唯一约束。
