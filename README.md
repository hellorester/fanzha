# 反诈协同处置平台

Vue 3 + Spring Boot + Java 21 + MySQL 8，实现举报、研判、机构处置、社区劝阻、返还与申诉。以下命令均在仓库根目录执行。

## 启动与停止

已完成配置和构建时，只需启动一个服务，运行包已包含前端：

```powershell
java -jar .\backend\target\antifraud-1.0.0.jar
```

打开 <http://127.0.0.1:8088>。在运行窗口按 **Ctrl+C** 停止，重启不会清空数据。

同校园网访问时，改用下面的启动命令，再让其他设备打开 `http://电脑当前IPv4地址:8088`：

```powershell
java -jar .\backend\target\antifraud-1.0.0.jar --server.address=0.0.0.0
```

用 `ipconfig` 查看正在使用的网卡地址。其他设备访问还需防火墙允许该端口、校园网允许设备互通。

<details>
<summary>首次克隆：配置与构建</summary>

准备 JDK 21、Node.js 22.12+（或 24）、Maven 3.9 和 MySQL 8，确保 `java`、`npm`、`mvn` 可用。

1. 用 MySQL 客户端创建 `utf8mb4` 空数据库，授予应用用户该库的建表、迁移及读写权限。
2. 复制 [配置模板](config/application.example.properties)，填写自己的数据库地址、库名、用户名和密码：

   ```powershell
   Copy-Item .\config\application.example.properties .\config\application.properties
   notepad .\config\application.properties
   ```

3. 为**新空库**生成应用密钥，将输出填到配置的 `app.key`：

   ```powershell
   $keyBytes = New-Object byte[] 32
   $rng = [Security.Cryptography.RandomNumberGenerator]::Create()
   $rng.GetBytes($keyBytes)
   [Convert]::ToBase64String($keyBytes)
   $rng.Dispose()
   ```

4. 构建，再按上面的命令启动；首次启动会建表并初始化账号和基础资料。

   ```powershell
   npm.cmd --prefix frontend ci
   npm.cmd --prefix frontend run build
   mvn -B -f backend\pom.xml clean package
   ```

更新源码后，先停止服务再重新构建。队友使用各自的数据库和配置；`config/application.properties` 不提交到 Git。

## 手动验收

以下是操作清单，需实际执行并核对结果。

- 从头验收建议使用独立空库：另建库名、配置和附件目录，保留原配置；不要清空日常业务库。
- 先走完主线，再做分支。拒绝、作废、到期等分支应另建用例，不能对已经办结的记录反复操作。相同受害人在归并窗口内的未结束预警会合并；需要独立用例时，先结束前案或使用新的实名人员。
- 记录受理号、预警号、止付号和操作前余额。测试材料可用 [演示材料.txt](tests/fixtures/演示材料.txt)，金额按操作前后变化核对。

### 四角色完整主线

1. **群众举报（`public2`）**：进入“我的举报 → 提交举报”，选择账户、填写 `6222000000000001`；关系选“本人受损”，不勾匿名。填写经过、6000 元、23:30、异地交易，上传材料并提交。应得到受理编号和查询凭证，列表能打开本次举报。
2. **中心研判（`center`）**：在“举报与线索”打开该记录，点“查看关联预警”，查看五因子评分。点“核验关联账户”，选本次举报和尾号 0001，填写核验依据；再点“人工复核 / 补录”，通过、确认居民二与云栖社区、填写意见。点“联动派发”，选择尾号 0001，止付金额 6000。应生成一条止付及一条上门任务。
3. **机构执行（`pay1`）**：在“协同指令”按止付号打开详情，先“受理指令”，再“核查后提交回执”，选全额执行 6000 元并提交凭证。原账户可用余额减少 6000、剩余冻结增加 6000，中心能看到同一回执。
4. **网格回传（`grid3`）**：进入“上门劝阻”，找到该任务并“接收任务”；“记录到场”填写当前时间及坐标，例如纬度 `30.300001`、经度 `120.100001`；“回传结果”填写过程、选择已完成并上传材料。任务应变为已回传。
5. **中心办结（`center`）**：回到该预警，核对机构回执和网格反馈，点“确认办结”填写意见。预警已闭环，上门任务已归档；原冻结仍按自身期限和后续申请办理。
6. **资金返还**：`public2` 在“返还与申诉 → 资金返还”选择该止付、本人尾号 0004 收款账户，申请 1000 元并上传证明；`center` 打开申请“中心审核”，通过并核定 1000。此时实际入账应为 0、待执行占用为 1000。`pay1` 受理返还指令并提交全额执行回执后，列表及详情实际入账均为 1000；原剩余冻结为 5000、占用为 0，收款账户余额增加 1000。
7. **误冻结申诉**：`public3` 对本人尾号 0001 的该止付提交申诉；`center` 先受理，再裁定成立。此时只生成解除指令；`pay1` 受理并提交“解除成功”回执后，剩余 5000 元回到原账户，原止付结束。已返还的 1000 元不退回；相较操作前，原账户净减少 1000、收款账户净增加 1000。
8. **核对结果（`center`）**：在“资金账户 → 资金对账”检查无差异；在“操作日志 → 校验日志”检查通过。回到举报、预警和申请详情，沿关联记录核对审核、指令和回执。`public2` 不能作尾号 0001 的户主申诉，`public3` 不能以居民二的身份申请返还。

### 其他业务分支

| 场景 | 操作 | 应看到的结果 |
|---|---|---|
| 匿名举报与查询 | 退出登录，从首页“我要举报”提交；保存凭证，在“进度查询”输入；再输错凭证 | 正确凭证可查进度，错误凭证不返回内容；中心可在举报详情重置、停用凭证，旧凭证失效 |
| 号码、网址及上门核查 | `public1` 分别用“提供线索 / 代他人举报”提交号码、网址；中心核实当事人与社区，复核后“派发上门核查”，对应网格员回传 | 不自动把举报人当受害人，不自动绑卡；只派上门任务也能办结 |
| 线索归并与补充复核 | 同一已确认受害人在窗口内追加举报；中心查看原未结束预警并补充复核 | 关联线索增加；复核前不能新派止付或重发，复核后保留原任务，不重复派单 |
| 驳回、作废 | 分别用两条新预警测试人工复核“驳回”，以及机构未受理、网格未到场前“作废” | 预警结束，不能继续派发；作废同步结束未执行任务 |
| 同账户与跨机构派发 | 对同一预警、同账户再次派发；再核验尾号 0002、补充复核后派发 | 前者复用有效指令；后者新增城西指令，由 `pay2` 办理，共用原上门任务 |
| 拒绝、超时与重发 | `pay1` 拒绝执行并填写原因，中心从原指令“复核重发”；超时场景可用 `center` 的“时效检查 → 超时”另测 | 普通派发不能绕过失败指令；重发保留原指令关系。追加线索时须先补充复核，闭环后不能重发止付 |
| 部分执行与回执更正 | 另案申请止付 6000，机构部分执行 3000；在无返还、申诉等后续业务前“申请更正”为部分执行 4000，中心在“回执更正”审核 | 审核前仍冻结 3000；批准后为 4000，保留原回执及更正对照；不批准时金额不变 |
| 返还补正与申诉维持 | 返还被中心驳回后，群众“补交材料”再审核；另案申诉先受理、要求补正、户主补交后裁定维持 | 补正保留原申请；维持不解除冻结，同一止付不能重复提交已维持的申诉 |
| 多笔返还 | 另案冻结 1000，分别申请并核定 600、400，先执行 400，再执行 600 | 第一次后剩余冻结和占用均为 600；最终累计入账 1000，冻结及占用为 0，各申请显示自身实际入账 |
| 到期、全额返还收尾 | 另案保留待核定返还、待补正申诉，再到期释放或通过另一申请全额返还；另测部分入账后到期 | 未完成待办结束并注明原因，不能继续执行；已入账金额保留，部分入账显示“部分入账（已结束）” |
| 延期与督办 | 在有效止付详情点“延期”；用“时效检查”推进 24 小时、2 小时、到期；到“时效与督办”打开提醒并处理 | 延期次数、期限更新；提醒可跳转原指令；到期释放余额，不能继续执行或延期。此操作会改变数据，仅用于独立用例 |
| 网格改派与异常办结 | 为青禾社区任务指定 `grid1`，到场前改派 `grid2`；后者回传“未完成”并填写原因，中心从督办查看、追加说明、异常办结 | 仅当前负责人可办理；未完成进入上门督办，办结后归档并退出队列，过程记录保留 |
| 研判失败恢复 | 若出现“人工待研判”，中心在原举报详情点击“重新研判” | 保留原受理号、材料，成功后可查看关联预警；正常验收不必人为制造数据库故障 |

### 管理与内容模块

| 模块 | 操作与验收 |
|---|---|
| 实名人员 | `center` 新建人员，填写证件、电话、社区及核验依据；更正资料须写理由。重复证件不能重复登记，姓名更正同步本人账户户名 |
| 资金账户 | 登记新账号、机构、期初余额、实名户主及依据；按机构、户名、完整账号搜索。详情核对归属；未用于业务的误录账户可更正户主，已有业务时应拒绝改归属 |
| 账号管理 | 分别新建群众、中心、机构、网格账号：群众选核验状态及人员，机构必须选机构，网格必须选社区，中心可选管理权限。切换角色应清除无关字段；保存后逐个登录核对菜单。测试重置密码、停用与重新启用，旧会话应失效；不要停用唯一管理员 |
| 首次实名与身份保护 | 新建未核验群众账号，先举报再关联新实名人员，应成功但不自动确认历史受损身份；另一个启用账号关联同一人、有业务的实名账号改绑他人，都应被拒绝 |
| 风险名单 | `center` 新增号码、账户、网址名单，测试搜索、修改、停用；新举报查看名单因子是否命中。`reviewer` 只能查看，不能维护 |
| 规则配置 | 记录原配置，发布新权重或阈值；权重合计非 100、高阈值不大于中阈值时不能提交。合法版本出现在历史中，新研判使用新配置，旧评分版本保留；测试后恢复原参数 |
| 社区宣防 | 中心新建青禾任务，截止时间选未来；`grid1` 登记宣传形式、任务期间且不晚于当前的活动时间、场次和人数。中心核对汇总并完成；另建任务测试取消。结束后不能打卡，`grid3` 不能办理青禾任务 |
| 反诈知识 | 中心新建文章，上传 PNG/JPG 封面，先存草稿再发布；退出登录查看分类、搜索和正文。编辑、更换或移除封面后应同步，未设置封面使用默认图；下线后公众不可见 |
| 协同总览 | 各角色调整日期、点击更新，核对趋势及数量；中心导出汇总。机构仅统计本机构，网格统计本社区，群众统计自己的业务 |
| 操作日志 | 中心按关键词、日期及页面提供的条件筛选，核对操作人、业务动作和时间；管理员“校验日志”在居中弹窗显示结果，关闭后回到列表 |

### 通用交互与权限

- **首页**：观察轮播自动切换及手动切换；完成防骗小测三题、查看结果并重测。
- **列表**：搜索、状态和日期筛选、翻页、清空条件、刷新；空结果不显示上次记录。
- **附件**：上传、移除、取消后重开；已提交材料可由授权角色下载；超 10 MB 或不支持格式应提示失败。
- **权限**：其他群众看不到别人的举报、申请及附件；`pay2` 看不到钱塘指令；`grid3` 看不到青禾任务材料；`reviewer` 没有账号、实名人员等管理入口。
- **桌面与手机**：本机及另一设备分别打开首页举报、登录、菜单、详情、表单、资金对账；检查控件不重叠、弹窗居中可滚动、按钮可点。测试关闭按钮、Escape、快速切页和退出登录，不应残留上个账号的数据。

## 开发与数据维护

源码在 `frontend/src`、`backend/src`。单独运行基础测试：

```powershell
npm.cmd --prefix frontend test
mvn -B -f backend\pom.xml test
```

[GitHub Actions](https://github.com/hellorester/fanzha/actions) 在推送及 PR 时运行构建、单元测试、MySQL 业务与迁移回归。接口测试会写入数据，只对独立验证库运行；手动验收清单不代表已经实测通过。

升级前停止旧服务，备份数据库、附件目录和本机配置；启动自动迁移。**已有数据必须保留原 `app.key`**，备份恢复也要配套恢复密钥与附件。仓库不包含数据库、上传材料、本机配置和构建产物。

启动异常先查看终端及 `.local/logs/application.log`，检查 MySQL、配置和 8088 端口占用。
