# 反诈协同处置平台

本机已配置时，双击 **启动原型.cmd**，等到提示“原型已就绪”，在浏览器打开提示的地址，默认 <http://127.0.0.1:8088>。使用完双击 **停止原型.cmd**。重启后业务记录仍然保留。首次克隆请先完成下方的构建和本机配置。

| 中心管理员 | `center` |

| 青禾社区网格员 | `grid1`、`grid2` |
| 云栖社区网格员 | `grid3` |

统一演示密码：**`Demo2026!`**。它与数据库密码无关。登录时先选择群众用户、反诈中心、支付机构或社区网格，所选身份须与账号一致。更换角色先退出登录；同一浏览器普通标签页共享会话。

## 操作顺序

1. `public2` 提交举报：账户 `6222000000000001`、6000元、23:30、异地，可上传 `tests/fixtures/演示材料.txt`。
2. `center` 核实举报并查看五因子评分，选择模拟账户1，派发止付与云栖上门任务。
3. `pay1` 受理并提交回执。`grid3` 领取任务，记录到场，填写过程和材料后回传。
4. `center` 核对两端结果并办结。返还、申诉、时效、宣传与管理可从对应菜单办理。

已有验收案例已走过后续返还或解除流程，重演请新建举报。全部居民、账户与材料均为虚构演示数据。银行资金、身份核验和坐标采用模拟；权限、规则、状态、金额约束和数据库保存真实执行。

## 源码与维护

前端位于 `frontend/src`，后端位于 `backend/src`。技术栈为 Vue 3、Spring Boot、Java 21 和 MySQL 8。本机已构建的 `backend/target/antifraud-1.0.0.jar` 包含前端资源，直接运行不需要另开Vite。Git仓库只保存源码，首次克隆需先构建。

本机重新构建：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Start.ps1
```

`Build.ps1` 自动查找 Java、Node/npm，使用仓库自带 Maven Wrapper，默认联网安装锁文件中的依赖。构建不需要数据库连接和密码。已有完整依赖缓存时可加 `-Offline`；仅需要构建且明确跳过单元测试时可加 `-SkipTests`。

备份使用 `scripts/Backup.ps1`，MySQL命令行工具从本机设置、PATH、MYSQL_HOME、安装注册表或常见安装目录查找。`Restore-Verify.ps1 -BackupFolder "完整备份目录"` 默认恢复到“当前数据库名_verify”，使用8089端口；可通过 `-TargetDatabase` 和 `-Port` 指定已创建的独立验证库及端口。该验证库需要事先创建并授权，不能指定为当前业务库，恢复会覆盖验证库内同名表。结束时执行 `Stop-Verify.ps1`。

## 已做的检查

本轮修复覆盖任务材料权限、止付更正边界、同步超时、宣防截止时间、重复派发、URL匹配、规则溢出、附件清理和旧数据升级。前端附件生命周期测试、后端单元测试以及独立 MySQL 验证库的主线、并发、边界和迁移测试均有相应脚本。

`.github/workflows/ci.yml` 在向 `main` 推送和提交 PR 时执行前端测试及构建、后端测试及完整打包、MySQL 实际接口回归和旧数据迁移检查，测试报告保留7天。CI仅使用临时数据库与自动生成的密钥，不读取任何开发者的本机配置。

本机前端测试可在 `frontend` 中执行 `npm test`；`Build.ps1` 默认包含后端单元测试。接口测试通过 `TEST_BASE_URL` 指定测试实例；SQL边界测试还需 `TEST_DB_NAME`、数据库连接及 `APP_KEY`，仅允许独立的 `antifraud_*verify` 或 `antifraud_*ci` 验证库。综合测试会生成业务数据，不应对日常业务库执行。

此前还完成过四角色29个页面入口、10万条虚构数据及20个独立账号的容量检查、数据库及附件恢复和本机启停验证。这些历史容量结果不代表每次改动都重新跑过压力测试。本机结果保存在 `tests/results`，运行记录不上传Git仓库。

工具路径和本机配置另通过27项脚本检查，并在不含数据库配置的全新目录完成构建；备份、独立库恢复及自定义端口启停已实测。可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tests/portable_scripts.ps1` 重做脚本检查，该检查使用临时目录，不连接业务数据库。

启动失败时先看窗口提示和 `.local/logs`，确认自己的MySQL服务运行且应用端口未被其他程序占用。脚本面向 Windows PowerShell 5.1及以上，macOS/Linux需自行使用等价的环境变量和启动命令。

## 首次从仓库构建

准备 JDK 21、Node.js 22.12以上及 MySQL 8，设置 `JAVA_HOME` 或把Java加入PATH，并把Node/npm加入PATH。先在仓库根目录构建，不用复制他人的数据库配置：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build.ps1
```

首次构建需要联网下载Maven和依赖，无需单独安装Maven。然后在自己的MySQL中建立utf8mb4数据库和专用用户，执行本机配置。例如自己建立的数据库名为 `fanzha_dev`、用户为 `fanzha_user`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Configure.ps1 -Database fanzha_dev -Username fanzha_user -HostAddress 127.0.0.1 -Port 3306
.\启动原型.cmd
```

脚本在本机提示输入数据库密码；它只保存连接配置，不创建数据库或数据库用户。`-Port` 是MySQL端口，`-AppPort` 是网页端口，默认8088。应用首次启动会创建表和虚构基础资料。已有配置会拒绝覆盖；更改连接地址或端口可以编辑自己的 `.local/database.json` 后重启。不同电脑的库名、账号、密码和端口无需一致。

## 不同电脑的工具路径

一般只需配置环境变量，不用修改脚本。Java按 `.local/tools.json` 的 `javaHome`、`JAVA_HOME`、PATH查找；Node按 `nodeHome`、`NODE_HOME`、PATH查找。MySQL客户端仅在备份及恢复时需要。

特殊安装目录可把 `scripts/tools.example.json` 复制为 `.local/tools.json`，仅填写需要覆盖的字段。例如：

```json
{
  "mysqlBin": "E:/Software/MySQL/bin",
  "mavenUserHome": "E:/DevCache/maven",
  "npmCache": "E:/DevCache/npm"
}
```

`javaHome` 指向JDK根目录，`nodeHome` 指向含node.exe和npm.cmd的目录，`mysqlBin` 指向含mysql.exe和mysqldump.exe的目录。路径支持空格，JSON建议使用正斜杠。`mavenUserHome` 控制Wrapper缓存，并默认使用其repository子目录保存Maven依赖；`mavenRepository`可单独覆盖依赖目录。未设置时沿用当前电脑的环境变量与默认缓存。

`.local`已被Git忽略，自己的工具路径和数据库配置不会提交或覆盖队友配置。密码及应用密钥使用当前Windows用户的DPAPI保存，请各自初始化，不复制他人的 `.local`。

数据库升级由 `Migrations.java` 按版本执行，成功版本记录在 `af_migration` 中。启动完成升级与基础资料初始化后才开放接口。本轮会保留既有业务记录，将号码、账户及URL的索引升级为由现有应用密钥派生的 HMAC 指纹，同时规范化旧URL。升级前应运行 `scripts/Backup.ps1`；恢复时必须同时恢复数据和原应用密钥。

网格员可查看本社区待领取任务摘要及本人负责的任务；领取后才能查看居民和材料。回执更正目前支持止付，返还和解除保留原业务流程。宣传活动实际发生时间须在任务创建与截止时间之间，按时完成的活动允许事后登记。未关联材料可由上传人移除，每个账号或匿名会话最多暂存20份、合计50MB，超过24小时的未关联材料由后台清理；已提交材料不参与此清理。

本轮审查补充：群众举报的列表、详情、进度与举报附件统一按提交账号隔离，关联同一受害人不再自动共享举报。匿名凭证查询按连接来源每分钟最多60次，成功与失败均计数，更换会话不会重置配额；当前直连部署不采信客户端的转发IP请求头。举报详情的“管理查询凭证”可重置或停用凭证，旧凭证立即失效。匿名提交响应丢失时，在原提交会话中重试可取回同一受理编号与凭证；切换会话或遗失凭证后需联系中心核验，不提供无凭证找回接口。停用的凭证不会被旧请求重试恢复。

账户管理的“资金对账”独立核查账本连续性、有效回执、冻结余额、累计返还和待执行占用，并列出具体差异，不自动改账。冻结属于可用资金转为冻结资金；当前原型无充值或外部入金，核验关系为“期初余额－累计返还＝可用余额＋剩余冻结”。支付机构只能核验本机构。新库期初值来自初始化配置；旧库优先根据首笔流水反推，缺少流水则取升级时余额，分别标为“历史账本推算”“升级余额基线”，不能据此证明升级之前的记录完全正确。

操作日志的“校验日志”仅供管理员使用。关键日志在同一业务事务中串联带密钥的校验值，并维护链尾和条数；可以发现内容改动、断链、缺失尾部。旧日志在升级时建立校验基线，不能追溯证明此前未改动。这是本库内的篡改检测，不能抵抗同时取得应用密钥并重写整库，或将数据库与链尾一起回滚；不等同于外部只追加审计存储。

URL风险名单按主机、非默认端口与路径匹配，HTTP/HTTPS、查询参数与片段不作为区分项；因此同一路径下不同跳转参数会命中同一条规则，仍需人工复核。域名大小写、IDN、IPv6写法、未保留字符编码、点路径和连续斜杠统一；路径大小写保留，`%2F`等保留分隔符不会直接解码成斜杠，避免把不同路由盲目合并。`UrlRiskTest`明确覆盖这些命中与不命中边界，不声称能识别重定向后的网页内容。

升级时请停止所有连接同一业务库的旧版本实例，并先备份数据库、附件及应用密钥。迁移只移除历史索引 `af_blacklist.kind(kind,value_hash)`；若同名索引结构不同则中止并保留原结构，其他团队自建唯一索引保持不动。失败时不要删除迁移版本号或业务表来强行继续，先核对错误与索引；需回退时使用备份恢复完整数据库和对应附件、密钥，再运行备份时的代码版本。DDL不能保证与数据重算整体回滚，因此不能只回滚代码。已被旧版本迁移删除的未知索引无法自动恢复，应对照升级前备份处理。

`migration_safety.py`额外验证同名异构索引会中止升级、未知索引不会被删除，以及命名锁等待期间接口保持不可用、解锁后才完成初始化。后台业务扫描和附件清理也会等待初始化完成。

新增 `integrity_regressions.py` 使用实际HTTP请求与MySQL行锁重现附件绑定和后台清理重叠，同时验证数据库写入失败后的磁盘清理；`migration_regression.py`逐条检查3000条历史URL跨批迁移、记录数量和额外唯一索引，并记录重启及升级耗时。该规模用于回归，不代表生产数据量的性能保证；现有孤立文件恢复检查也不等同于所有崩溃时刻的故障注入覆盖。

仓库不含 `.local`、数据库口令、业务密钥、上传文件、备份、依赖目录、构建产物和本机测试输出。复制源代码不会带走现有业务数据。

本地演示的身份规则：举报始终属于提交账号；资金指令属于已核验受害人，一个受害人最多关联一个启用且已核验的群众账号。未核验账号不能绑定受害人，提交举报自动按匿名线索受理。旧库若存在重复核验关联，所有冲突账号暂时失去指令、回执和申请权限，但仍可查看各自举报，管理员解除重复关联后恢复。身份更换须先停用或解除原账号关联；新账号经管理员核验关联后接续该受害人的资金业务，历史举报仍不共享。

同来源举报与上传分别限制为每分钟120次，登录每分钟240次；已登录账号举报每分钟60次。登录失败记录保存在有过期时间的限流表中，同账号五分钟8次失败后暂缓登录，过期记录定期清除，不在内存中永久积累随机用户名。默认按直连地址限流，适用于本机演示。

图片在完整解码前检查尺寸（单边不超过10000、总像素不超过2000万），最多同时解码2张，并在解码进度回调中检查耗时；这不是严格的进程级超时隔离。DOCX验证完整ZIP内容，最多1000项、单项解压20MB、合计50MB，并检查处理时间。原有单文件10MB限制保留，不接入外部查毒服务。

合并预警在评分配置与名单版本未变化时只计算新线索，再与原最高分合并；版本变化则重新计算整组线索，保留历史评分记录。重发保留原指令关系，已重发指令不能再次重发或批准旧回执更正；并发业务按统一的身份、预警、指令、资金与审计顺序锁定记录。审计页面分别显示本次校验时间和历史校验链建立时间。

`local_review_regressions.py`覆盖重复身份与未核验权限、匿名重复请求及失败恢复、评分版本变化、重发与更正竞争、资金锁等待期间重复派发、上传解压限制和基本限流。保留本地课程原型的规模：不新增公网部署、验证码、外部审计存储、异步资金队列或大数据量全量对账调度。
